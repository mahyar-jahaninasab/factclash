## 1. Context

Bloating the context window with Retrieval-Augmented Generation (RAG), dynamic web search, or user-supplied prompts introduces a critical vulnerability: the emergence of knowledge conflicts within the model's context window. A fact clash occurs when pieces of information presented in the context window contradict one another, or when contextual information conflicts with the model's pre-trained parametric memory.

To protect response factuality and system reliability, we must introduce an automated context validation and contradiction detection mechanism prior to final answer generation.

## 2. Decision Drivers

* **Latency Constraints:** Real-time production endpoints enforce strict low-latency SLAs.


* **Operational Cost Efficiency:** Running high-parameter LLM-as-a-Judge evaluations on 100% of retrieved document pairs scales token consumption quadratically ($O(N^2)$).


* **Detection Accuracy & Multi-Hop Depth:** Surface-level pattern matching fails to identify implicit, temporal, or multi-hop conditional contradictions.


* **Noise Robustness:** The detection pipeline must remain stable when handling noisy or uncurated text within the context window.



## 3. Decision

Adopt a two-stage hybrid pipeline combining a lightweight NLP layer for fast surface-level screening with selective deferral to an LLM judge for complex or low-confidence edge cases.

## 4. Consequences

A pure NLP-based solution has extremely low latency and zero API token cost, but it struggles with multi-hop reasoning and implicit context clashes. On the other hand, a pure LLM-centric evaluation handles multi-hop logical parsing and high nuance, but introduces significant API token cost and execution latency.

### 4.1 Pros

* **Cost Savings:** Cuts API token costs significantly compared to pure LLM evaluation by passing the majority of non-conflicting pairs through the fast filter.


* **High Accuracy:** Maintains high overall detection accuracy by deferring complex multi-hop conflicts to the LLM judge.


* **Low Average Latency:** Preserves low-latency response times for the vast majority of non-conflicting retrieval requests.



### 4.2 Cons

* **System Complexity:** Requires deploying, orchestrating, and monitoring two separate model components (the fast NLP classifier and the LLM judge).


* **Threshold Sensitivity:** Demands careful empirical calibration of the confidence threshold used to trigger Stage 2 LLM routing.


* **Subjective Conflict Limitations:** Performance on subjective or opinion-based conflicts remains lower than on explicit factual contradictions.
